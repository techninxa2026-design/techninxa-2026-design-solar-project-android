# Self-hosted updates
Version 1.0.1+2 introduces update checking at startup, resume and every 60 seconds while foregrounded; automatic prompts occur on the root route once per version per app session. Account -> Check for app updates is available after login. The server toggle suppresses automatic prompts only. APKs are downloaded from a fixed HTTPS origin without redirects, checked against published byte length and SHA-256, then the installed package name, version and signing certificate. Android presents installation confirmation. A user may need to allow installs from IDCOLDA, return, and press Update now again. No silent installation.
Build with the original permanent release keystore: set IDCOLDA_KEYSTORE (absolute path), IDCOLDA_STORE_PASSWORD, IDCOLDA_KEY_ALIAS, IDCOLDA_KEY_PASSWORD in your local environment or CI secrets. Run flutter build apk --release --build-name 1.0.1 --build-number 2 (increase on every upload). Upload build/app/outputs/flutter-apk/app-release.apk in MVC SuperAdmin App Update. A debug-installed copy usually needs a one-time manual installation of the release-signed app; incompatible signers cannot update in place. Back up any local data before uninstalling. Do not use a debug key for production or commit keystore secrets. This direct-distribution build is not intended for Google Play self-update; use Play's own update flow for a Play distribution flavor. Test APK signing, upgrade preservation, denied permission, interrupted network, bad checksum, wrong signer, toggle and QR on real devices.

## Automatic build
GitHub Actions workflow `IDCOLDA signed Android release` validates each relevant push to the main branch and, if the four signing secrets are set, builds a universal signed APK artifact. Configure repository or appropriately accessible environment secrets IDCOLDA_KEYSTORE_BASE64, IDCOLDA_STORE_PASSWORD, IDCOLDA_KEY_ALIAS, IDCOLDA_KEY_PASSWORD; keep a securely backed-up permanent key. The workflow uses the version name from pubspec and build number 10000 + workflow run number. Reserve this numbering range for CI (manual builds should not exceed the latest CI build number unless the workflow counter is adjusted). A rerun of a previously published build is not a newer release. The workflow automatically publishes to MVC after validation when the publishing token and server verification are configured. The APK artifact is also retained for recovery or manual upload. No direct IIS filesystem access is needed. Missing signing secrets prevent signed artifacts.

The public QR now points directly to https://idcoldrs.com/app/download. Publishing in MVC automatically changes both the QR's download and the update manifest; no new QR is required. Manual update checking works with the automatic prompt switched off. If publication changes during an in-app update, a retired version download returns 404 and the client checks the latest manifest again before offering another update. It does not install mismatched bytes or silently retry an installation.

## Automatic website publication
The signed Android release workflow now publishes directly to MVC after validation, building, and APK signature verification. The workflow uses the separate IDCOLDA_PUBLISH_TOKEN secret, configured on both the IIS server and GitHub using the MVC script Scripts/Enable-AndroidAutoPublish.ps1. No routine manual upload is required. The fixed QR URL and update metadata change automatically. The automatic update-message toggle remains controlled by SuperAdmin, with off as the default for the first release. The existing signing secrets and server APK verifier are required. Failed validation/build/publication must not replace the previous APK. The workflow skips stale branch commits and rejects lower or duplicate conflicting version codes. It confirms the published SHA-256 and version via the public manifest.

Every push to main now triggers the release workflow, preventing an unrelated later commit from silently suppressing a queued release without a replacement run. Android SDK setup occurs before validation. Publication checks the authenticated VPS readiness route and compares the built APK signing certificate with the VPS certificate, then verifies the actual direct QR download SHA-256. Deploy the latest MVC main before dispatching this workflow. If the workflow reports missing signing secrets, configure the permanent release key using the repository's Actions secrets (or Scripts/Set-AndroidSigningSecrets.ps1 in this repository).

## CI runner SDK setup
Both Android workflows use ubuntu-24.04 and Scripts/setup-ci-android-sdk.sh to locate the installed Android command-line tools explicitly, export the SDK paths to subsequent steps, accept licenses and ensure API 36/build tools 36.0.0 exist. Flutter/Gradle retains JDK 25; sdkmanager uses the runner's JDK 17 if available. This avoids exit 127 from a missing sdkmanager PATH entry (actions/runner-images#13674). Run a new workflow on main after changing the workflow; rerunning an old failed commit uses the old workflow.
