# Self-hosted updates
Version 1.0.1+2 introduces update checking at startup, resume and every 60 seconds while foregrounded; automatic prompts occur on the root route once per version per app session. Account -> Check for app updates is available after login. The server toggle suppresses automatic prompts only. APKs are downloaded from a fixed HTTPS origin without redirects, checked against published byte length and SHA-256, then the installed package name, version and signing certificate. Android presents installation confirmation. A user may need to allow installs from IDCOLDA, return, and press Update now again. No silent installation.
Build with the original permanent release keystore: set IDCOLDA_KEYSTORE (absolute path), IDCOLDA_STORE_PASSWORD, IDCOLDA_KEY_ALIAS, IDCOLDA_KEY_PASSWORD in your local environment or CI secrets. Run flutter build apk --release --build-name 1.0.1 --build-number 2 (increase on every upload). Upload build/app/outputs/flutter-apk/app-release.apk in MVC SuperAdmin App Update. A debug-installed copy usually needs a one-time manual installation of the release-signed app; incompatible signers cannot update in place. Back up any local data before uninstalling. Do not use a debug key for production or commit keystore secrets. This direct-distribution build is not intended for Google Play self-update; use Play's own update flow for a Play distribution flavor. Test APK signing, upgrade preservation, denied permission, interrupted network, bad checksum, wrong signer, toggle and QR on real devices.

## Automatic build
GitHub Actions workflow `IDCOLDA signed Android release` validates each relevant push to the existing feature branch and, if the four signing secrets are set, builds a universal signed APK artifact. Configure repository or appropriately accessible environment secrets IDCOLDA_KEYSTORE_BASE64, IDCOLDA_STORE_PASSWORD, IDCOLDA_KEY_ALIAS, IDCOLDA_KEY_PASSWORD; keep a securely backed-up permanent key. The workflow uses the version name from pubspec and build number 10000 + workflow run number. Reserve this numbering range for CI (manual builds should not exceed the latest CI build number unless the workflow counter is adjusted). A rerun of a previously published build is not a newer release. Download the artifact from Actions and upload the APK to the MVC release manager. No automatic production publication and no CI access to the IIS server. Missing signing secrets prevent signed artifacts.
