# Form and NID capture acceptance notes
Shared on-input validation for authentication and operational forms; API payloads unchanged. Server ProblemDetails field errors are shown when safe and available; current MVC field-only errors do not supply an exact reason.
Profile front and back open a themed camera/gallery scanner. Latin OCR and PDF417/MRZ evidence are used locally. Wrong-side, mixed or insufficient evidence is rejected; not authenticity or government database verification. Older Bangla-only reverse sides without readable English or MRZ can be rejected. Test both card variants on a device before production. Never use real NIDs in automated tests or logs. Test permission denial, background/resume, gallery cancel, wrong side, both sides, corrupt image, >2 MB, duplicates, profile save and existing image replacement. No database migration.

Android camera support now requires Android 7.0 / API 24 or later. Scanner capture uses full still images (the overlay is a positioning guide, not automatic crop). The current client-side checks do not prove both images belong to one person.
